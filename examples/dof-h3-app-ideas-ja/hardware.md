# 前提知識：DOF Reality HERO H3 上で動くアプリの企画

本ファイルは、企画出しの土台となる**事実資料**である。ここに書かれた範囲を超えて
スペックやAPIを捏造してはならない。断定できない事項は「未確認」と明記してある。

---

## 0. 最初に外せない前提：H3 は「コンピュータ」ではなく「動く台」である

`https://rk-online2020.net/products/dof-h3` の実機は **DOF REALITY 製 HERO H3**
というモーションシミュレータ・プラットフォームであり、**計算機ではない**。

- CPU・OS・ディスプレイ・ストレージ・アプリストアは**存在しない**。
- 「この実機にインストールする」とは、**H3 を USB で繋いだ Windows PC 側に
  ソフトウェアを入れて、そのソフトが H3 を動かす**という意味になる。
- つまりアプリの実体は PC 上のプログラムであり、H3 はその**出力デバイス**
  （キネステティック／身体感覚のディスプレイ）である。

この構造を踏まえないアイデア（例：「H3 単体で動くアプリ」「H3 の画面に表示する」
「H3 にマイクを繋ぐ」等）は**成立しない**。

**企画の核心的な問い**：H3 は「画面」ではなく「身体」に出力する。この出力先の
特異性を活かさないアイデアは、PC ゲームの焼き直しに留まる。

## 2. 何ができて、何ができないか（運動能力の制約）

3軸機であり、**6自由度ではない**。この制約が企画の輪郭を決める。

**できる（3軸）**
- **ピッチ** … 前後の傾き（加速感・ブレーキ感・機首上げ下げ）
- **ロール** … 左右の傾き（旋回の遠心力・傾き）
- **ヨー／リアトラクション** … 後部モーターによる横滑り・車体の向き変化の再現

**できない（重要）**
- **ヒーブ（上下の並進移動）** … 段差・着地・浮遊の「持ち上げ」は直接再現できない
- **サージ（前後の並進移動）** … 前進そのものの移動感は出せない
- **スウェイ（左右の並進移動）**
- 3軸機のため、上下動は**傾きで錯覚させる**（チルト・コーディネーション）しかない。
  「持ち上がる」「落下する」を主役にする企画は、実機では**期待通りに動かない**。

**時間特性**
- 可動範囲 20° は**狭い**。大きな揺れは物理的に不可能。
- 速度 86°/秒 は**速い**が、可動域が狭いため「短く鋭い動き」が得意。
- 1000W ピーク。連続的な激しい運動は電力・発熱・騒音・摩耗の面で不利。
- 0.7G T。1G 未満であり、実加速度を完全に再現することは原理的に不可能。
  **「錯覚させる」ことがこのデバイスの本質**である。

**騒音・設置**：3基のモーターとギアボックスが動く。リビングに置ける静音機器ではない。
利用は1日2〜3時間程度が想定されている。

## 3. ソフトウェアの構造：アプリはどこで動くのか

**確認済みのデータ経路**

```
[あなたのアプリ]  --UDP:33001-->  [SRS アプリ]  --USBシリアル-->  [モーションボックス]  --PWM-->  3モーター
                   (apiパケット)                  (Arduino UNO R3)
```

または、SRS を介さない直接制御：

```
[あなたのアプリ]  --USBシリアル 500000 baud-->  [モーションボックス]  --PWM-->  3モーター
```

**モーションボックスの正体**：Arduino UNO R3 ベース。ファームウェアは
オープンソースの SMC3 スケッチ由来。H3 は**1台**のコントロールボックスに
3モーター（H6/P6 は2台）。3軸は SMC3 が標準対応する構成そのもので、
H3 はむしろ**制御しやすい側**の機種である。

**重要な排他制御**：COM ポートを握れるのは**同時に1プロセスだけ**。
SRS や SimHub が動いている間は直接制御できない（＝置き換えであって併用ではない）。

**SRS 常駐時のライセンス**：SRS でモーションを動かすには Base License が必要
（DOF Reality のパッケージには同梱される）。Premium（$19.99/年）は
ジョイスティックモーション等の追加機能で、API テレメトリには不要。

## 4. 開発ルート（実装難易度順）

### ルートA：モーションボックスへ直接シリアル送信 ★最も自由度が高く、ライセンス不要

- **プロトコル**：`[` + コマンド1文字 + 値HI + 値LO + `]` の**5バイト固定長**、ビッグエンディアン。
  - `[A<hi><lo>]` モーター1、`[B…]` モーター2、`[C…]` モーター3（値は 0〜1023、中央 512）
  - `[ena]` 全モーター有効化（接続時に必要）、`[sav]` EEPROM保存、`[ver]` バージョン問い合わせ
- **シリアル設定**：**500,000 baud**、8データビット、パリティなし、ストップビット1
- **既存ライブラリ**：`pysmc3`（Python、Apache-2.0、`pip install smc3`）。
  DOF Reality のコントロールボックスで動作確認済みと明記されている。
- **H3 固有の実測知見**（実機ファーム v33.07 での報告）：
  - **約15秒間コマンドが来ないと出力が絞られる（ウォッチドッグ）**。
    アイドル時も**継続的にストリームを送り続ける必要がある**。
  - ファームウェア設定により**有効範囲が狭められている**（実測例：入力クリップ 220〜803）。
    範囲外を指令しても動かない。
  - 応答ストリームにはデバッグ文字列が混ざる。固定長読みをしてはならない。
  - ファームウェアは**範囲を検証しない**。ホスト側が制限を守る責任を負う。
- **長所**：SRS 不要、ライセンス購入不要、サードパーティ依存なし、低遅延、
  ピッチ／ロール／ヨーを完全に掌握できる。**「何でも動かせる」**。
- **短所**：安全装置・レート制限・COMポート探索を**自分で実装する責任**。
  SRS/SimHub とは併用不可。DOF Reality のサポート対象外。

### ルートB：SRS へ UDP パケットを送る ★公式サポートあり・最小コード

- SRS は**公式の公開 API** を持つ（v1.43.2 以上）。サンプルコードは **MIT ライセンス**。
- **送信先**：`127.0.0.1:33001`、**UDP**、片方向（応答なし・認証なし）。
- **パケット**：236バイト固定。先頭3バイトが `"api"`、続いてバージョン `102`。
  以降に `game` / `vehicle_name` / `location`（各50バイト文字列）、
  速度・RPM・ギア、**pitch / roll / yaw（度）**、
  **lateral_velocity（トラクションロスに使われる）**、各加速度、
  サスペンションストローク4輪分、路面種別4輪分が並ぶ。
- 公式ページは「レーシングゲーム**だけのものではない**」と明記しており、
  ローラーコースター、宇宙飛行、トラック／農業シム等を想定している。
  **自作の非ゲームアプリがこの構造体を送ることは、API の想定用途そのもの**。
- **長所**：公式・文書化済み・MIT サンプル・約30行で送れる。SRS が
  クセ取り・制限・チューニング・安全処理を全部やってくれる。
  すでに SRS を導入済みの H3 オーナーにそのまま届く。
- **短所**：SRS のインストールと Base License が前提。SRS のマッピングに従う必要がある。
  **プラットフォームの生の位置は指令できず、テレメトリを渡して SRS に解釈させる**形。
  ゲームが SRS を掴んでいる間は使えない。SRS 自身が「サードパーティ製プロキシは
  クラッシュ要因になり得る」と警告している。

### ルートC：SimHub を経由する

- SimHub は **SMC3 コントローラーをネイティブ対応**しており、H3 での動作報告がある
  （軸の分解能を **10ビット**に設定する指示付き）。
- 汎用シリアルコントローラー機能で任意プロトコルを定義できる。
- **長所**：巨大な既存ユーザーベース、豊富なエフェクト群。
- **短所**：**Motion Addon が有料**（約 €35、本体ライセンス約 €7 とは別）。
  プラグインからモーションを注入する方法は**文書化されていない**。

### ルートD：ファームウェアを書き換える

- SMC3 は MIT。Teensy 移植版や P6 向けの再実装が存在する。
- 計算余力・分解能・挙動を根本から変えたい場合のみ。**サポート外・高リスク**。

**「シンプルに作れる」の観点での結論**：
配布して多くの H3 オーナーに使ってもらうなら **ルートB**（SRS は DOF Reality に同梱され、
すでに動いている）。自分専用の実験・作品として振り切るなら **ルートA**（依存ゼロ、
ライセンスゼロ、ただし安全は自前）。

## 5. ライセンス・コストの整理

- SRS サンプル API コード：**MIT**（自由に利用・再配布可）
- SRS アプリ本体：モーション動作に **Base License 必須**（買い切り）。DOF Reality に同梱
- **SMC3 ファームウェア：MIT／pysmc3：Apache-2.0**（直接制御は**ライセンスフリー**）
- SimHub Motion Addon：**有料**
- FlyPT Mover：個人利用は無料
- DOF Reality 公式アップデータ：プロプライエタリ、純正ファームのみ受け付ける

**未確認**：SRS API には**開発者向けの利用規約・レート制限・再配布条項が公開されていない**。
「ユーザーの PC 上で SRS に喋るアプリを配布する」場合の条件は未定義。
問い合わせる以外に解決手段がない。→ **配布前提の企画では、この不確実性を織り込むこと**。

## 6. 安全上の必須事項

H3 は**人が乗った状態で 25 N·m のトルクで動く**。ソフトウェアの不具合が
そのまま身体の危険になる。アプリ企画には以下が**設計要件として**含まれるべき：

- **可動範囲のクランプ**：ソフトウェア側で必ず制限内に収める（ファームは検証しない）
- **変化率制限（スルーレート）**：指令値の急変を平滑化する。逆 braking は abrupt
- **ハートビート**：アイドル時も送り続ける（約15秒でウォッチドッグが働く）
- **非常停止**：即座に中央へ戻す手段を必ず用意する
- **起動時の原点復帰**：いきなり飛ばさない
- **搭乗者の体重上限 150kg**、**シートは別売**である点

「シンプルに楽しめる」の前提として、**「シンプルに止められる」**が要る。

## 7. 既存の周辺事例（重複回避のための参照）

以下は**すでにある**。アイデアはこれらとの差分で測られる。

- **レーシング／フライトシム**：iRacing, Assetto Corsa, rFactor 2, MSFS, DCS World,
  X-Plane, Euro Truck Simulator 2 など100タイトル以上が SRS 経由で対応済み
- **ローラーコースター／宇宙飛行／トラック・農業シム**：SRS の API ページが想定用途として例示
- **SRS v2.9+ の Intellitune**：3分の解析で最適設定を提案する AI チューニング
- **VR モーションコンペンセーション**：SRS に統合済み。Witmotion センサーとの併用が定番
- **FlyPT Mover**：無料。SMC3 出力モジュールあり。ただし **DOF Reality のリグ寸法プロファイルが
  存在しない**（開発者が寸法を求めたが得られず、H3 ユーザーは手動でジオメトリを組んでいる）
- **SimTools**：旧来のモーションソフト。DOF Reality が以前同梱していた
- **Unreal Engine「Motion Platform Linker」プラグイン**：SRS 公式の UE 連携ルート
- **オープン標準の動き**：Open Motion Alliance / Open Game Standards Alliance が
  UE からモーションソフトへ送るパケット標準を策定中（MIT）。まだ実用段階ではない

**空白地帯（＝企画の候補地）**：上記はほぼ全て**「乗り物のシミュレーション」**である。
身体感覚を**他の目的**に使う事例は、ローラーコースター（＝これも乗り物）を除いて
ほとんど見当たらない。

- **一次ユーザー**：H3 を **¥680,000〜¥815,800** で購入した個人。すでに PC と SRS を持ち、
  レーシングシムを一通り遊んでいる。**追加でソフトに金を払う余力はあるが、

## 9. 未確認・要注意事項（断定してはならない）

1. SRS がモーションボックスへ送るシリアルの実ログは未確認（SMC3 系譜から強く推定されるのみ）
2. 約15秒のウォッチドッグと有効範囲の実測値は**単一情報源**（実機での計測報告）
3. SimHub の**プラグインからモーションを注入できるか**は、肯定・否定とも文書が見つかっていない
4. SRS API の開発者向け規約・レート制限は**存在が確認できていない**
5. H3 の既定ビット深度は 10ビット（0〜1023）と見られる。12ビットは他機種の話
6. DOF Reality の**サードパーティ製制御ソフトに対する保証・サポート姿勢**は公式表明が見つかっていない
7. ベース寸法「100×150, 60 cm」の正確な読み（奥行×幅×高さか、他か）は不明
8. 加速度「0.7G T / 0.5G L」の T / L の定義（Tangential / Lateral と推測）は未確認

## 10. この企画で満たすべき要件（タスク側の制約）

- **シンプルに作れる**こと。個人が現実的に完成させられる規模・依存関係であること。
  有料ライセンス・非公開 SDK・未文書のAPIに依存する企画は減点。
- **シンプルに楽しめる**こと。説明書を読まないと楽しめないものは減点。
  インストールして、座って、すぐ身体が動くこと。
- **H3 の身体出力を活かす**こと。画面で完結する企画、PC ゲームの焼き直しは減点。
- **3軸の制約を正直に扱う**こと。ヒーブ／サージを前提にした企画は実機で破綻する。
- **安全に止められる**こと。
