# 出力形式（OutputFormat）

- 成果物種別: 設計仕様書
- 説明: 最新AIを核とし、公共空間で子どもを含む不特定多数が安全に遊べる体感ゲーム用モーションプラットフォームの設計仕様を、レーシング/フライトシミュレータとの差別化を明示して示したもの。
- 出力長の範囲: 2500〜12000 字
- 成果物そのもの: いいえ（成果物についての分析）

## 草案の形式指示（draft_guidance）

設計仕様の骨子として、以下を項目立てして書く。(1) コンセプト命題：この遊具が提供する体感の正体を一文で定義し、なぜレーシング／フライトシミュレータではないのか（操縦・速度・遠隔移動の模倣ではなく何を体感させるのか）を対比で明示する。(2) 機構仕様：可動軸・自由度・ストローク・加速度上限・駆動方式を数値で。乗員姿勢と支持方法。(3) AI核の役割：知覚（乗員の動き・表情・声の推定）、生成（動く世界・応答・難易度）、適応（習熟と飽きの推定）を、どの入出力で担うかを列挙する。(4) 安全設計：対象年齢・体格差の吸収、非常停止、可動範囲の物理的制限、公共空間での順番待ちと衛生。(5) 遊戯体験：1回あたりの所要時間、上達の可視化、子どもと大人が同一装置で成立する設計。(6) 差別化の根拠：既存の体感型アトラクション・家庭用VRとの差異を、体感の種類の違いとして述べる。各節には前提（想定設置環境・想定人数・想定予算帯）と、その設計判断の根拠を一文ずつ添える。数値・軸構成・AI入出力は必ず具体値で書き、断定を避けた一般論（「臨場感を高める」「安全性に配慮」）で埋めない。

## 最終化の形式指示（finalize_guidance）

以下の見出し構造で最終成果物を組み立てる。①『コンセプト』：体感の定義一文と、レーシング／フライトシミュレータではない理由の対比表（体感の種類／操作の主体／失敗の意味）。②『プラットフォーム機構仕様』：自由度・可動域・最大加速度・駆動方式・乗員支持・体格適応範囲を数値表で。③『AI核の構成』：知覚・生成・適応の三層それぞれについて、入力信号、処理内容、出力（世界の変化／難易度／応答）を対応表で。④『公共遊具としての成立条件』：安全（非常停止・物理制限・年齢体格）、運用（1回の所要時間・順番待ち・清掃・故障時挙動）、不特定多数への公平性を箇条で。⑤『遊戯体験の設計』：習熟曲線、子どもと大人の同居、リピート動機。⑥『差別化の明示』：既存の体感アトラクション／家庭用VR／レーシング系との差異を、体感の種類の違いとして断定調で。⑦『未解決の設計課題』：前提が崩れた場合に再検討が必要な点を列挙。全体として、材料（与えられた止揚の基盤）にある結論のみを誠実に仕上げ、材料を超えた推論・追加の世界設定・実在しない技術の捏造は加えない。各節の主張は根拠（前提条件）と一対で示し、過不足なく明瞭に表現する。
