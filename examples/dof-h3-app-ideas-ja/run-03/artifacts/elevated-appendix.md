# 付録：『明け渡しの深さ』読解ガイド

本文（[elevated.md](elevated.md)）を読み解くための補助資料である。

やっていることは三つだけ —— 本文の主張を平易な日本語に言い換える／本文に出てくる記号・専門語・数値を説明する／**どこが確定情報で、どこが未検証かを仕分ける**。

**本文にない新しい主張は加えていない。** 語の定義と、本文の言い換えだけを置く。

---

## 1. 30秒でわかる全体像

- この企画は、H3 を「乗り物を再現する機械」として使わない。使うのは**「身体の制御をどこまで台に明け渡したか」という一点**だけ。
- その明け渡しの深さを **σ（シグマ）** と名づける。
- σ には**外から見える部分（σ_out）**と、**AI が推論するしかない部分（σ_in）**がある。
- **この二つの食い違いがゲームの全部である。** 食い違えば「違う」という身体感覚が返る —— これがこの企画における「失敗」の定義になる。
- **操作機器はゼロ。** 乗員は何も操作しない。AI が身体を読み、台が動き、身体が答え合わせをする。

---

## 2. 主役は σ ——「明け渡しの深さ」

### 2.1 σ とは何か

本文の定義はこうである。

> 体感とは、乗員が自分の身体の制御を台に明け渡す深さ **σ** を、台が3軸回転として返し、乗員の前庭が答え合わせをする過程である。

言い換えると —— 人は立っているときも座っているときも、無意識に筋肉で姿勢を保っている。その保ち方を**どれだけ手放して台に任せたか**が σ である。

```
乗員が身体の制御を明け渡す（σ の深さ）
        ↓
台がそれを 3軸回転として返す
        ↓
乗員の前庭が「合っているか」を答え合わせする
```

本文④に**「起動時は σ=0。台は動かない」**とある。つまり **σ=0 とは「何も委ねていない」状態**であり、そのとき台は静止したまま**60秒で静かに終わる**。委ねるかどうかの主導権は、最初は乗員の側にある。

### 2.2 σ_out と σ_in —— ここが本文の核心

| | **σ_out** | **σ_in** |
|---|---|---|
| 何の深さか | 外から見える明け渡し | 外から見えない明け渡し |
| 手がかり | 姿勢・支持・拘束 | 筋緊張・重心動揺・把持力・呼吸 |
| 誰が読めるか | 観客にもカメラにも見える | **本人にも正確にはわからない。AI が推論するしかない** |
| 例 | 立位か仰臥か、ハーネスの選び方 | どれだけ力んでいるか、どれだけ息を止めているか |

ふつうのゲームは「外から見える行動」を測る。この企画は**「本人にも見えない内面」を測ろうとする**。ここに AI が必要になる理由がある（本文③「身体を持たないものが身体を仮定する」）。

### 2.3 なぜ「ズレ」が商品になるのか

| | 一致している | 食い違っている |
|---|---|---|
| 本文での呼び方 | ——（本文に呼称はない。スコアが高い状態） | **読み違え**（＝失敗） |
| 本文の記述 | ——（本文に感覚の記述はない） | **σ_outとσ_inの不一致＝「違う」という身体感覚** |

本文の対比表がこれを一文でまとめている —— レーシング／フライトシミュレータの失敗は「クラッシュ・タイムロス＝操作の巧拙」だが、**本機の失敗は「読み違え」であって上手い下手ではない**。

だから**スコアは σ_out と σ_in の一致度**になる。操作でも耐久でもない。

### 2.4 なぜ体重をそろえなくていいのか（本文②の数式）

本文②にこうある。

> 転倒閾値 m·g·h·sinθ において**質量は約分され消える**ため、正規化変数は体重ではなく**幾何**。

m（質量）· g（重力）· h（重心の高さ）· sinθ —— **「どれだけ傾いたら倒れるか」を決める式では、重さは打ち消し合って消える。** 残るのは**重心の高さや支えの幅といった「形」**である。体重の違う人でも、形が同じなら同じ角度で倒れる。

そのうえで本文は二段構えで効かせている。

1. **体格差の正規化に体重を使わない。** 使うのは幾何（体格・重心の高さ）。
2. **そもそもスコア自体が体格非依存。** 一致度は操作でも耐久でもないので、正規化そのものが要らない（本文④「不特定多数への公平性」）。

ただし**生理差は残る**と本文は明記している —— 筋力・反応時間・頸部の強さ。これは σ の上限として別に扱う（本文②末尾）。

## 3. 用語集

本文に出てくる語を、初出順ではなく**意味のまとまりごと**に並べる。

本文が説明せずに使っている**H3 側の前提語**（機械・実装の語）も、読むのに要るので混ぜてある。印は付けていないが、「機械」「実装」の2表はほぼそれにあたる。

### 身体（本文①）

| 用語 | 意味 |
|---|---|
| **前庭（ぜんてい）** | 耳の奥にある**平衡感覚の器官**。**「前提」ではない**（同音異義）。本文では「身体が重力と動きを感じ取る側」の意味で使われる |

### 企画の中心

| 用語 | 意味 |
|---|---|
| **σ（シグマ）** | 明け渡しの深さ。身体の制御を台に預けた度合い |
| **σ_out** | 外から見える明け渡し（姿勢・支持・拘束） |
| **σ_in** | 本人にも見えない明け渡し（筋緊張・重心動揺・把持力・呼吸）。AI が推論する側 |
| **予告量（＝本文③の「難易度」）** | 台が動く前に「次はこう動く」とどれだけ教えるか。**読めていない乗員には予告を情報として与え、よく委ねられる乗員には予告の不在を「委ねた甲斐」として与える**——これが本文③の難易度の正体 |

### 安全機構（本文③④）

| 用語 | 意味 |
|---|---|
| **上位ガバナ** | **AI の自信を一切参照しない**ハードリミット。σ に依存せず、常に同じ制限をかける |
| **下位AI** | σ に応じて動く運用側。**ガバナの内側でしか動けない** |
| **クランプ** | 指令値を一定範囲に収めること。本機は 220〜803 |
| **スルーレート制限** | 指令の変化速度を制限し、急変をならす |
| **ウォッチドッグ** | 約15秒指令が来ないとファームが出力を絞る機構。だから**常時ストリームが必要** |
| **512復帰** | 中央＝中立へ戻すこと。異常終了時の挙動 |

### 機械（本文②）

| 用語 | 意味 |
|---|---|
| **リアトラクション** | 後部モーターによる横滑り・車体の向き変化の再現。3軸のうちの一つ |
| **チルト・コーディネーション** | 並進（上下動）を傾きで錯覚させる技法。本機は上下動を持たないため、これしかない |
| **転倒閾値** | どれだけ傾くと倒れるかの限界。§2.4 の数式 |

### 実装（本文②⑦）

| 用語 | 意味 |
|---|---|
| **ルートA** | モーションボックスへ**直接シリアルで指令する**開発経路。専用ライブラリは Apache-2.0 で、**有料ライセンス不要**。本企画はこれを前提とする |
| **Pi5＋5060ti級** | 想定する計算機の規模（Raspberry Pi 5 ＋ RTX 5060 Ti 級の GPU） |

## 6. 本文が決めきれていないこと（⑦の言い換え）

本文⑦は6項目。平易にするとこうなる。

1. **AI が本当に身体を読めるか** —— σ_in のリアルタイム推論が、Pi5＋5060ti 級の構成で実用水準に届くかは**未検証**。カメラ姿勢推定＋ロードセル＋把持力の融合は実機計測が要る。
2. **「AI の自信」に安全を連動させてよいか** —— 自信が外れたときに危険側へ振れる可能性があり、**安全性が未証明**。最悪の場合、自信を参照しない固定マージンへ後退する。
3. **σ は観客に伝染するか** —— 会場の σ 分布が時間とともに変わる、というのは**仮説**。
4. **加速度の表記が読めない** —— 0.7G T / 0.5G L の T / L の定義が未確認なので、σ の物理的な限界値を確定できない。
5. **誰が運営するのか** —— 公共性＝拒否可能性を貫くなら、「乗りたくない人が乗らずに済む」だけでなく**「貸したくない人が貸さずに済む」**ことも保証しなければならない。**その条件は導出できていない。**
6. **公共で連続稼働に耐えるか** —— H3 は本来**1日2〜3時間**の利用を想定した機体。公共での連続稼働（1000W ピークの発熱・摩耗・騒音）は想定を超える。耐久の実測が必要。

## 7. 読むときの注意

- **「前庭」は「前提」ではない。** どちらも「ぜんてい」と読むが、前庭は耳の奥にある平衡感覚の器官である。本文①「乗員の前庭が答え合わせをする」は、前提に置き換えると意味が通らない。**同じ本文に通常の意味の「前提」（想定設置環境・想定人数など）も出てくる**ので、読み分けには注意が要る。
- **数値の出所を確かめる。** §4 の「性質」欄を見ること。①販売ページ記載と③実測報告（単一情報源）は重みが違う。
- **本文自身が「仮説」「未証明」「未検証」と書いている箇所を尊重する。** σ の伝染（⑦-3）、AI の自信と安全の連動（⑦-2）、σ_in 推論の実用水準（⑦-1）がそれにあたる。
- **本文⑤の「作るとは AI に身体を与えることである」は体験の説明であって、実装の手順ではない。** 実装の前提は②のルートAと③の三層（知覚／生成／適応）のほうにある。
- **本文⑥の「AI の身体性の欠如そのものを唯一のルールにする」は、この企画の設計原理の宣言である。** AI を難易度調整や見た目生成に使う企画（＝構想が批判する側）との断絶はここで引かれている。
