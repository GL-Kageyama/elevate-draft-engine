# DOF Reality HERO H3 企画提案書 ―― 「重力の感じ方」を書き換える機械のためのアプリ

## ① 前提整理 ―― H3 で物理的に何ができ、何ができないか

**できる（3軸回転のみ）**
- ピッチ／ロール／ヨー（リアトラクション）の**回転3軸**。可動範囲 **20°**、速度 **86°/秒**、トルク **25N·m**。
- 得意なのは**短く鋭い動き**と、**低速域の滑らかな軌道**。範囲が狭く速度が高い＝小さく速い運動に最適化されている。

**できない（並進）**
- **ヒーブ／サージ／スウェイは不可**。段差・着地・浮遊・前進そのものの移動感は出せない。
- 上下動は**傾きによる錯覚（チルト・コーディネーション）でのみ**扱える。0.7G＝1G未満であり、実加速度の完全再現は原理的に不可能。**この機械の本質は「錯覚させること」**。

**体感の性質（企画の核心）**
- 前庭系（耳の奥にある平衡感覚の器官）が受け取るのは角度ではなく**重力ベクトルのずれ＝「どちらが下か」の変調**。20°の狭さは欠如ではなく、**「重力の向き」への特化**である。上下の並進は重力の向きを変えないため、3軸で足りる。

**PC接続上の制約**
- H3 は計算機ではない。**PC側アプリが USB 経由で動かす出力デバイス**。
- **COM ポートを握れるのは同時に1プロセスだけ**（SRS／SimHub と併用不可）。→ **単一ランタイム＋プリセット構造が物理的に強制される**。
- 経路：ルートA＝直接シリアル **500,000 baud・5バイト固定長 `[A<hi><lo>]`・値0〜1023/中央512**、pysmc3（Apache-2.0）で**ライセンス不要**。ルートB＝SRS へ **UDP:33001・236バイト**（既存 SRS 層向けの明示オプション）。
- **約15秒でウォッチドッグ**（アイドル時も送信継続が必要）、**有効範囲が狭められている**（実測例 220–803）、**ファームは範囲を検証しない**。→ 制限・レート・緊急停止は**すべてアプリ側の責任**。

## ② 候補企画一覧

いずれも共通ランタイム（クランプ／スルーレート／15秒ハートビート／原点復帰／1キー中央復帰／COM排他）の上の**プリセット**として実装される。

**A. 呼吸が決める重力の感じ方（推奨）**
- 核心理念：自分の呼吸が「重力の感じ方」を決める。揺れは入力に追随するのではなく、**呼吸の周期そのものを書き換える**。
- 3軸の使い方：pitch のみ ±1.5°、0.15–0.4Hz。ロール／ヨーは静止。
- 非焼き直し根拠：車両もゲームも画面も存在しない。入力は PC のマイク1本、出力は身体のみ。
- 最小実装：マイクRMS → バンドパス → 振幅・周期 → pitch角。ループが既に閉じている（呼吸→揺れ→呼吸）。
- 利用シーン：就寝前・作業後の5〜15分。シートに座るだけ。

**B. 重力の感じ方の共有（遠隔平衡）**
- 核心理念：遠くの人の「重力の感じ方」と自分の「重力の感じ方」を一致させる。**視覚的再現は一切不要**。
- 3軸の使い方：相手の姿勢（ロール／ピッチ）を ±2〜3° に縮約して提示。
- 非焼き直し根拠：既存100タイトルはすべて「搭乗者＝操作者」。ここでは**搭乗者は受信者**。
- 最小実装：スマホの姿勢センサ→UDP→PC→pitch/roll。または揺れファイルの非同期再生。
- 利用シーン：離れた家族・友人と、通話なしで「同じ世界に立つ」。

**C. 揺れのボイスメモ（BODY TAPE）**
- 核心理念：揺れは**ファイルになる**。3軸指令は時刻＋角度の時系列であり、録音・圧縮・送信できる。
- 3軸の使い方：記録された pitch/roll/yaw の再生。
- 非焼き直し根拠：メディア形式の発明。既存の動画・音声に対する**身体感覚の記録媒体**。
- 最小実装：セッション中の指令値をCSV保存（`t,roll,pitch,yaw`）、再生はその逆。数十行。
- 利用シーン：「今日の地震、これ」と1ファイル送る。B の非同期版としても機能。

**D. 地震が動かす重力の感じ方**
- 核心理念：地面が動いた、という**「重力の感じ方」についての直接の主張**を身体に届ける。
- 3軸の使い方：地震波形の低周波成分を pitch/roll へ ±2° 程度に縮約。
- 非焼き直し根拠：加速度データは本質的に「重力の感じ方」の変動であり、写像が情報を捨てない稀有な例。
- 最小実装：公開波形ファイルの再生（C のプリセットとして実装可能）。
- 利用シーン：防災教育・記念日・純粋な好奇。

**E. アンコール（操作権の外在化）**
- 核心理念：**搭乗者は操作者ではない**。台を操るのは同席者・観客・サイコロ。
- 3軸の使い方：他者入力またはランダムイベント列を ±3〜8° で鋭く提示。
- 非焼き直し根拠：応答主体の反転。既存の全タイトルが固定している「操作する者／される者」を逆転。
- 最小実装：テキスト譜面（`時刻,軸,角度,保持ms,攻撃ms`）のイベント列再生。C と同一エンジン。
- 利用シーン：友人を座らせる。1回限りの逸話製造。

## ③ 推奨案 ―― **A. 呼吸が決める重力の感じ方**

**シンプルに作れる**：入力が PC のマイクで完結し、追加ハードが不要。振幅 ±1.5° は安全域が最も広く、クランプ・スルーレートの検証が容易。車両モデルも物理演算もゲーム連携も要らず、**ランタイム＋数十行**で動く。B/C/D/E は後から**同じランタイム上のプリセット**として足せる。

**シンプルに楽しめる**：起動と同時に一つの「重力の感じ方」が始まる（選択画面を作らない）。画面を見ない、説明書を読まない、座れば身体が動く。そして**ループが既に閉じている**——自分の呼吸が揺れを作り、揺れが呼吸を変える。止めるのは物理キー1つで即中央。「シンプルに楽しめる」の前提は「シンプルに止められる」であり、これを最初の一本で満たす。

## ④ 却下・保留案

**却下**
- **株価・勾配などの数値写像**：これらのデータは「重力の感じ方」について何も主張していない。写像は成立せず、情報の損失を体験と呼び替えることになる。
- **「他人が攻撃する」型**：攻撃者／被攻撃者の非対称は固定され3分で飽きる。抗う身体は疲労と安全の問題を生む。
- **オペレーター付きアトラクション／外部支払い者前提**：タスク要件は「PC から駆動して楽しむ」であり、遊具の提供ではない。
- **画面・VR 前提の再現系**：レースシムの強さは台ではなく画面の強さだった。画面を持つことは台の貧しさを補うこと。

**保留**
- **B. 重力の感じ方の共有**：最も射程が広いが、遅延・欠落・切断が身体に直撃する。安全設計と通信断処理が重く、**一本目には置かない**。
- **D. 地震が動かす重力の感じ方**：C のプリセットとして実装コストほぼゼロで載るため、単独企画としては保留。
- **E. アンコール**：C と同一エンジン。逸話は評価軸だが最大化の対象ではなく、**副産物**として扱う。

## ⑤ 最小実装ステップ

1. **環境**：Python ＋ `pip install smc3`（pysmc3）。H3 のモーションボックスを USB 接続し、COM ポートを特定（同時に他プロセスが握っていないことを確認）。
2. **安全ランタイムを先に書く**：①角度クランプ（初期値は実測 220–803 を採用）②スルーレート制限 ③100ms 間隔のハートビート（15秒ウォッチドッグ回避）④起動時の原点復帰（いきなり飛ばさない）⑤例外・異常終了時も中央へ ⑥SPACE キーで即中央。
3. **無入力で動作確認**：中央付近 ±1.5°・0.2Hz の正弦を30秒出力し、自分の機体の実際の有効範囲と挙動を実測する（ファームは検証しないため、ここは実機で確かめるしかない）。
4. **マイク入力を足す**：`sounddevice` 等で RMS を取得し、0.15–0.4Hz のバンドパスで呼吸周期を抽出。振幅と周期を pitch 角（±1.5°）へ変換。
5. **ループを閉じる**：出力した揺れが呼吸を誘導する。画面も音も出さない。
6. **プリセット化**：パラメータ（軸／中心角／振幅／周期／attack 時間）を外部定義に切り出す。以後の案はここに数行で追加。
7. **保存形式（BODY TAPE）**：`t,roll,pitch,yaw` の時系列をCSV保存し、再生機能を付ける。これで B／C／D／E の非同期共有まで射程に入る。

**注記**：ヒーブ／サージは扱わない。上下動は傾きによる錯覚のみとし、提案・説明のいずれにおいてもそれを約束しない。
