# 出力形式（OutputFormat）

- 成果物種別: 設計仕様書（コンセプト設計・システム仕様）
- 説明: 公共空間に設置され子どもを含む不特定多数が遊ぶ、AIを核とした体感ゲーム用モーションプラットフォームの仕様を、非レーシング／非フライトである遊びの原理・身体とAIの関係・安全と運用の成立条件まで含めて過不足なく記述した設計文書。
- 出力長の範囲: 2000〜7000 字
- 成果物そのもの: いいえ（成果物についての分析）

## 草案の形式指示（draft_guidance）

分析的テーゼ形式で記述せよ。各草案は次の四点を明示すること。(1)核心的主張——このプラットフォームが成立する遊びの原理を一文で（例:「身体の動きをAIが即興の相手役に変換する」等、レーシング／フライト以外の操作対象・目的を明確に定義）。(2)根拠——なぜそれが体感ゲームとして機能するか、AIを核とする必然性（知覚・生成・適応のどこをAIが担うか）を具体的に。(3)前提——公共空間・不特定多数・子ども同伴という制約条件（設置面積、待ち時間、衛生、転倒、音量、照明、多言語・低リテラシー、係員不在）を列挙。(4)排除の証明——レーシング／フライトシミュレータの焼き直しではないと言える理由を、操作・評価軸・失敗の意味づけの三点で対比せよ。草案段階では候補となる遊びの機構を複数（3案以上）出し、各案に『身体の使い方／AIの役割／一回の遊戯時間／成立する年齢層』を添えること。抽象語（「直感的」「革新的」等）のみの記述は不可。

## 最終化の形式指示（finalize_guidance）

最終成果物は一つの設計仕様書として、以下の見出しをこの順で備えること。①コンセプト宣言（プラットフォーム名、遊びの一文定義、レーシング／フライトとの非同一性の宣言）②遊びの原理（プレイヤーの身体入力→AIの解釈／生成→返ってくる体験、のループを段階的に記述。AIが担う知覚・生成・適応の役割を分離して明記）③プラットフォーム仕様（ハードウェア構成：センシング方式、表示・音響、可動部の有無と安全域、想定設置面積／ソフトウェア構成：AIモデルの入出力、応答遅延の許容値、同時参加人数、セッション長）④公共遊具としての成立条件（子どもの身体寸法・リーチへの適合、転倒・挟み込み・接触への対策、衛生と清掃、待機列と順番の設計、音量・光の配慮、多言語・非識字者への案内、無人運用時の復帰手順）⑤遊戯体験のバリエーション（同一プラットフォーム上で成立する複数の遊びモードと、その難易度・対象年齢の幅）⑥運用・保守・更新（AIモデル更新の方針、故障時の縮退運転、データ取得とプライバシー方針）⑦限界と未解決課題（現時点で検証が必要な仮定を明示）。各節は断定で記述し、根拠なき将来予測や材料外の数値捏造を避けること。図が不要でも要素間の対応関係が読み取れる箇条書きを用いること。
