# 付録：『まわしよみ』読解ガイド

本文（[elevated.md](elevated.md)）を読み解くための補助資料である。

やっていることは三つだけ —— 本文の主張を平易な日本語に言い換える／本文に出てくる記号・専門語・数値を説明する／**どこが確定情報で、どこが未検証かを仕分ける**。

**本文にない新しい主張は加えていない。** 語の定義と、本文の言い換えだけを置く。

---

## 1. 30秒でわかる全体像

- この台は、**前の人の身体についてのAIの仮説**が既に載っている状態で始まる。
- あなたはそれを見ない。台がそれをそのまま実行し、あなたの身体は前の人とは違うので**必ず外れる**。
- あなたが違和感に抗うと、AIがそれを読んで仮説を直し、また動かす。**外れ方が内容になる。**
- 終わると、あなたについての仮説が一行に圧縮され、次の人へ渡る（**連鎖長1**）。**あなた自身の読みは、最後まであなたには見せられない。**
- これを支えているのが**二チャネル分離** —— 台を動かす経路は正確で、**AIを通さない**。AIが触るのは意味の側だけ。

---

## 2. 中心の反転 ——「軸自由度の不足が、社会自由度の増加を強制する」

本文①のこの一文が、この設計の全体を決めている。

> 軸自由度の不足が、社会自由度の増加を強制する。

### 2.1 「まわしよみ」という名前

**回し読み** —— 一枚の紙を隣の人へ渡して順に読ませること。この台で回っているのは紙ではなく、**前の人の身体についてのAIの仮説**である。

| 回し読み | この台 |
|---|---|
| 回ってくるもの | 前の人の身体についての**一行の仮説** |
| あなたがすること | それを**自分の身体で試す**（抗う） |
| あなたが残すもの | あなたについての**一行の仮説** |
| あなたが読めるか | **読めない**。自分の読みは最後まで見せられない |

本文①の一文定義がすべてを言っている。

> 前の人の身体についてのAIの仮説を、あなたの身体で試される台。あなたは抗うことで自分の癖を露見させ、次の人のための仮説を一行だけ残す。**あなた自身の読みは、最後まであなたには見せられない。**

### 2.2 なぜ「貧しさ」が「社会」を強制するのか

本文①の論の運びはこうである。

1. 従来の体感ゲームは「**一人の運転者が一人の身体で一台と対話する**」1自由度の社会を前提している。
2. 本機は **並進ゼロ・20°・1G未満**という貧しさを持つ。移動そのものを偽装できない。
3. だから一人の身体と一台の対話では成立しない。**残るのは「身体そのものを扱う」ことだけ**である。
4. ところが身体は一人に一つしかない。**他人の身体と突き合わせるしかない。**

その結果、搭乗者は同時に三つの身体として扱われる（本文①）。

| | 誰に読まれる身体か |
|---|---|
| **(a)** | **AIに読まれる身体** |
| **(b)** | **行列に読まれる身体** |
| **(c)** | **次の搭乗者に継承される身体** |

**軸の自由度を諦めたぶんが、社会の自由度に回っている。** これがレーシング／フライトとの差だと本文は言う —— 差は軸の自由度ではなく、**観客の自由度**である。

### 2.3 一行の仮説とは何か

1プレイ45〜60秒は、6段のループである（本文②）。

```
装填  前の人の仮説が既に入っている。乗り手は見ない
  ↓
提示  台が仮説をそのまま実行する。別の身体なので必ず外れる
  ↓
抗い  乗り手が違和感に抗う。説明はゼロ。抗いが癖の露見になる
  ↓
解釈／生成  AIが抗いを読み、仮説を修正して再実行。外れ方が内容になる
  ↓
残留  仮説を一行に圧縮して次の人へ。乗り手には見せない。連鎖長は1
  ↓
摩耗  台の運動余力が減り、次の人の生成包絡を狭める
```

押さえるべきは三つ。

- **外れは失敗ではない。** 仮説は別の身体のものなので外れるのが前提で、**外れ方が内容**になる。
- **抗いは入力である。** 操作機器はないが、抗うことがそのままAIへの入力になる。
- **渡るのは一人ぶんだけ**（連鎖長1）。仮説が積み上がって抽象化していくのではなく、常に隣の人へ一本だけ渡る。

### 2.4 二チャネル分離 —— 本文を貫く設計の要

本文②のこの一文が、設計の要である。

> 運動チャネルは正確（クランプ・スルーレート・質量正規化。**生成モデルを経路に置かない**）。意味チャネルは不正確。**両者の接続部がゲームである。誤読が腰に来た瞬間にだけ、AIの読みは意味を持つ。**

| | **運動チャネル** | **意味チャネル** |
|---|---|---|
| 何をする | 台を正確に動かす | 仮説を読み、生成する |
| 中身 | クランプ・スルーレート・**質量正規化** | 知覚・生成・適応 |
| 生成モデル | **経路に置かない** | それ自体が生成モデル |
| 遅延 | 問題になるのはここだけ | **数十秒まで許容**（仮説はプレイ前に装填済み） |
| モデル更新 | **凍結・バージョン固定・監査可能** | 更新可 |
| カメラ／マイク | **非依存**（無くても成立＝縮退運転） | 依存 |
| 安全層 | **AIの出力は必ずここを通る**（決定論層） | 関与しない |

**AIが安全に関与しないこと**と、**AIが不正確でよいこと**が、同じ一つの分離から出ている。これが本文の一番おいしいところである。

**なぜ AI が要るのか**（本文①）：体重差は物理では解けない。150kg から軽い子どもまで、**同一の指令が体格によって別の運動になる**。だから**推定質量によるトルク正規化は生成モデルなしには成立しない**。AIは演出ではなく、**運動が成立するための条件**である。

## 3. 用語集

本文が説明せずに使っている語を、**意味のまとまりごと**に並べる。「機械」「実装」の表は、H3 側の前提語である。

### 遊びの単位

| 用語 | 意味 |
|---|---|
| **一行の仮説** | 前の人の身体についてのAIの推測。台に装填され、実行され、外れ、修正され、また一行に圧縮される。**これが台を巡っていく** |
| **外れ** | 仮説があなたの身体に合わないこと。**失敗ではなく内容**。「外れ方が内容になる」 |
| **癖** | 抗いによって露見する、あなたの身体の傾向 |
| **連鎖長1** | 仮説が渡るのは**次の一人だけ**。積み上がらない |
| **装填／提示／抗い／解釈・生成／残留／摩耗** | 1プレイの6段（§2.3 の図） |

### 設計の要

| 用語 | 意味 |
|---|---|
| **二チャネル分離** | 運動チャネル（正確）と意味チャネル（不正確）を分けること（§2.4） |
| **決定論層** | AIの出力が必ず通る後段。**AIは安全層に関与しない** |
| **質量正規化** | 体格差をトルクに反映させること。同一指令が体格で別の運動になるため必須 |
| **生成包絡** | その人に出せる運動の範囲。広いほど細かく読める。**台が疲れると狭くなる** |
| **観客の自由度** | 軸の自由度に対する語。**何人ぶんの身体が関与するか**。本文はここで差別化する |

### 遊びのモード（本文⑤）

同一機構のまま、**仮説の粒度**と**出所**だけを変える。

| モード | 対象 | 仮説の出所 |
|---|---|---|
| **よみあて** | 初見・4歳〜 | 粗い仮説（大きい動き・二択）。外れが必ず可視化される |
| **まえのひと** | 標準・小学生〜 | 直前の一人の仮説。**基本形** |
| **けいしょう** | 上級 | その日の匿名仮説プール。抽象度が上がる |
| **てんき** | 終盤 | **台の疲労が主役**。狭い余力でどう遊ぶか |

### 安全と運用

| 用語 | 意味 |
|---|---|
| **E-stop** | 非常停止。**開始ボタンとは兼用しない**（開始＝台上の子どもでも押せる／停止＝台外の誰でも） |
| **縮退運転** | カメラ／マイクが無くても成立させる運転。運動チャネルは非依存 |
| **疲労モデル** | 指令デューティ積算＋起動からの経過時間から**運動余力**を推定し、生成包絡に反映する |
| **台の天候** | 運動余力の可視化。**行列が見る**。行列の集合的行動が台の状態を作る |
| **一日で消える図書館** | 共有画面の一日分を**閉場時に消去**し、抽出・販売・二次利用を**設計上不可能にする** |
| **恥の転換** | 外れを笑いに変えること。失敗した場合の戻し先が⑦に書かれている |
| **幻觉** | AIが事実にないことを生成すること。本文②では**歓迎**され、外れとして消費される |

### 機械・実装（H3 側の前提語）

| 用語 | 意味 |
|---|---|
| **COMポート排他** | COMポートを握れるのは同時に1プロセスだけ。**制約ではなく設計原理** —— だから**仮説はプロセスではなくファイルとして持ち回される**。単一ランタイムだからこそ連鎖が成立する |
| **ルートA** | モーションボックスへ直接シリアルで指令する経路（`pysmc3`／Apache-2.0／500,000 baud／5バイト固定長／`[ena]`）。**SRS非依存・有料ライセンスなし** |
| **クランプ／スルーレート** | 指令値の範囲制限／変化速度の制限。**運動チャネルの中身**（本文②） |
| **ウォッチドッグ（約15秒）** | 指令が来ないとファームが出力を絞る機構。アイドル時も送り続ける必要がある。⑦で**単一情報源**と明記 |
| **感圧素子** | 座面に置く。**粗い質量推定のみ**に使う（意味チャネル側） |

## 6. 本文が決めきれていないこと（⑦の言い換え）

本文⑦は7項目。平易にするとこうなる。

1. **数値の裏付けが一つしかない** —— ウォッチドッグ約15秒・クランプ220〜803・ビット深度10ビットは実機計測報告が**単一情報源**。初期値として採用し、実機で追測する。
2. **モーターの状態が読めるか未確認** —— 電流値・位置フィードバックが取得できるか不明。**依存を足すなら、取得できないときの安全側縮退が必須**。（本文③は、取得できない前提で設計を書いている）
3. **公共で連続稼働に耐えるか** —— H3 は1日2〜3時間想定の個人・ホビー向け。発熱・摩耗・騒音の連続実測は未確認。ただし本文はここを弱点で終わらせず、**疲労モデルを「この想定外を可視化する装置」に転化している**。
4. **プライバシーと同意** —— カメラ／マイクの使用範囲と**子どもの同意主体**は運用・法務の領域として分離。運動チャネルがカメラ非依存で成立することを、縮退動作として保証する。
5. **恥の転換が失敗する場合** —— 外れが笑いにならず不快に留まるときの戻し方。実運用のチューニング対象。
6. **風営法** —— 呼称と設置形態の論点は残る。
7. **未決定** —— 疲労の実挙動、仮説の粒度と年齢の対応、外れの質の計測方法は、**プロトタイプ実測を待つ**。

## 7. 読むときの注意

- **数値の出所を確かめる。** §4 の「性質」欄を見ること。①販売ページ記載と③実測報告（単一情報源）は重みが違う。
- **「不正確でなければならない」は設計要件であって、妥協ではない。** 本文②は「誰であるか」の推定について「**正確＝遊びの終了**」と書いている。ここを「精度が足りない」と読むと、本文を逆に読むことになる。
- **「外れ」は失敗ではない。** 外れは内容であり、むしろ外れることが前提で回っている（§2.3）。
- **④の「子ども」の記述は、安全設計であると同時に遊びの設計である。** 初期の運動包絡を「最も小さく軽く壊れやすい身体」に設定すると、**安全と謙虚が同じ設定値になり、大人は最初の数秒だけ優しすぎる** —— 本文はそれを**最初の外れ**として使う。
- **「疲労モデル」は安全装置であると同時に遊びの装置である。** ⑤に「てんき」というモードがあり、⑥では台の状態が行列に開示され、**行列の集合的行動が台の状態を作る**。ただし疲労の実挙動そのものは⑦で未決定と明記されている。
- **画面は主役ではない。** 本文①は「意味は画面ではなく腰と背中で完結する」「**消しても遊びは成立する**」と書いている。画面の記述を探して本文を読むと、重点を外す。
- **⑦の「単一情報源」の括りには、実測値でないものが1つ混ざっている。** ウォッチドッグ約15秒とクランプ220〜803は実機の計測報告だが、**ビット深度10ビットは「そのように見られる」という推定の段階**である。本文⑦はこの3つを同じ括りで書いているので、§4 の表で分けてある。
