# Humanist草案

## 核心的主張

**「kiseki（軌跡）」**——全実行をビット完全な再現記録として自動保存するRust製エージェントランタイム。対象課題は信頼性。コンテキスト・ツール呼び出し・ループ・並列化のどの失敗も、結局は「あのときエージェントは何を見て、何をしたのか」に答えられない一点に収束する。Rustの所有権が「実行は入力と記録の純関数である」ことを構造的に保証し、実行器と再生器が**同一の単一バイナリ**であることで、過去の失敗実行をビット単位で巻き戻し、ブレークポイントを置いて生きた尋問ができる——隠れたメモリ状態を言語レベルで禁止しない限り、絶対に成立しない機能だ。

## 根拠

- LangChain/LangSmithのトレースは文字列とメタデータの記録に留まり、原因説明をモデル自身に生成させる——それは自己物語の捏造であり、感情の偽物と同じで私の基準では無価値だ。kisekiは生のバイト列と状態遷移を無欠落で記録し、結論は常に人間が下す。
- Python系エージェント基盤はGILとグローバルレジストリにより実行が周囲のランタイム状態に依存し、同じ入力が同じ結果を生む保証がない。所有権モデルで隠れ状態を排除するkisekiは、失敗実行の決定的再現を保証する。
- 既存の再現・再生機能は「遅いデモ」でしかない。kisekiのメモリマップドトレースは10万トークンの実行を数ミリ秒で巻き戻し、デバッグを発掘作業から生きた尋問へ変える。

## 前提

顧客に「なぜこれをした」と問われて答えられなければ契約を失う、受託エージェントを組む2〜20人の熟達チームが想定ユーザー。説明責任こそが購入条件であり、趣味の1人開発者やLangChainの大衆は対象外。
