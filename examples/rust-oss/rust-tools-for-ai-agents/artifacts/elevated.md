## Ephemeris（航海暦）——ツールコンセプト設計書

### 1. 名前とキャッチコピー

**Ephemeris（航海暦）**——「自由な一歩を、裁定し、記録し、分岐可能にする」。

天体の過去位置と未来位置を一つの表に収めた航海暦のように、来た軌跡（原簿）といま進むべき方向（憲章）を同一の道具が提供する、Rust製エージェント信頼層。

### 2. 対象ユーザーと解決する課題

対象は**本番マルチステップエージェントを運用する開発者**（複数ツール・サブエージェント・長期実行を抱えるチーム）。5課題カテゴリのうち主に**信頼性**と**エージェントループ**を解決し、**コンテキスト管理**（予算の裁定）、**ツール呼び出し**（スキーマ裁定）、**並列性**（クラッシュ原子原簿）にも対応する。課題の定義は「実行の可読性の欠如」に置き換える——確実性は保証せず、「何が提案され、何が許可・却下され、いくらかかり、そうでなければどうなっていたか」を知りうることを保証する。

### 3. 中核機能（Rustの強みとの対応）

1. **憲章コンパイラ**（静的）——状態機械の到達可能性・ツールスキーマ整合・予算の静的寄与・記憶の所有権をコンパイル時証明。→ 型システム・proc macro・借用チェッカー。
2. **裁定実行器**（動的）——モデルの提案を許可／修正／却下。却下時は根拠を返し再提案させる（自由は温存）。→ no-GC・ゼロコピーで**毎ステップ<1ms**の遅延SLO内執行。
3. **型付き原簿**（記録）——コンテンツアドレス・クラッシュ原子追記・mmap読取。→ 所有権によるCOW更新と原子的追記で、100万ステップ目でも監査証跡が引き裂かれない。
4. **逆実対航**（分岐）——任意の過去ステップの誓約を変更し未来を再導出する第三の操作（再演でも証明でもない）。→ 借用とイテレータにより分岐探索をメモリ安全に並列実行。

### 4. 差別化

| 既存ツール | Ephemeris |
|---|---|
| LangGraph（ループを所有） | ループを所有しない**憲法**として全ループに服属 |
| LangSmith（観測ログ） | 裁定を伴う実行可能な**原簿** |
| Temporal（プロセス固着） | **トークン粒度**の固着 |
| mypy/Pydantic（静的のみ） | 静的と動的の**誠実な境界** |

独自機能は**逆実対航**——「47歩目で別のツールを選んでいたら」を、憲章に合法なまま再導出できる。原簿が憲章をバージョン管理し、型（書く行為）と原簿（読む行為）が同一化する。

### 5. 想定アーキテクチャ

クレート：`ephemeris-core`（憲章型・裁定エンジン）、`ephemeris-ledger`（原簿）、`ephemeris-cli`（単一静的バイナリ）。配布はscp一発の**サイドカー**で、エージェント（Python/TS等）とはUnixソケット／stdinのJSON-RPC接続——言語移行を強要しない。GCなし・依存最小。メモリ安全性は差別化ではなく前提である。

### 6. MVPスコープと実装ステップ

1. **原簿プリミティブ**——コンテンツアドレス追記・fsync原子性・mmap読取（追記<10μs）
2. **憲章スキーマ＋裁定器**——ツール呼び出し・予算の許可／修正／却下
3. **逆実対航CLI**——`ephemeris branch <step>` による分岐再導出（差別化核）
4. **Python/TS SDK**——サイドカープロトコルで接続

数値目標：裁定<1ms/step、10万トークン巻き戻し<数ms（mmap）、単一バイナリ<10MB。

### 7. リスクと制約

- **市場**: フレームワーク群と観測群の中間市場が成立するか不確実。サイドカー採用は「配管」化されやすい——意見を持たない基盤は交換可能な部品になる。
- **技術**: 静的証明は開発者コードにしか及ばない。モデル出力は分布であり関数でないため、約束できるのは「可読性」であって「確実性」ではない。却下→再提案ループはトークン増を招く。
- **採用**: 決定性はRustの贈り物ではなく設計上の選択（シード・順序・I/Oの規律）。この規律をユーザーに要求する教育コストが残る。
