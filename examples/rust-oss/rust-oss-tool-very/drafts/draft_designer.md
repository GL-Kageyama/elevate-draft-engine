# 草案: `Simulacrum` — ビルドを実行しないビルドツール

## 核心的主張
Rust開発者が毎分行っている「ビルドして確かめる」という行為を、「ビルド成功の証明書を受け取る」という行為に置き換える——コンパイラを一度も実行せずに、コードの未来のビルド成功を現在の時点で導出し、署名付き証明書として返すツールを提案する。

## (1) ツール名
`Simulacrum`（CLI: `sim`）。出力物は実在のバイナリではなく、Rustの型検査公理と借用規則公理のハッシュをヘッダに持つ、暗号署名付き証明書 `.qed` である。コピーのない複製ではなく、**起動されなかったコンパイルの痕跡**。

## (2) 対象ユーザーと現在のワークフロー
モノレポでビルド待ち5分に囚われるRust開発者と、リグレッション恐怖症のライブラリ保守者。現在の流れ: コードを触る → `cargo build` → 祈る → エラーを直す → 祈る → コミット → CIでまた全ビルド。ビルドは毎回、世界の現状を再現し直す「儀式」だ。

## (3) 新しい枠組みで変わる動作の流れ
コードを触る → `sim` を叩く（20ms）→ 三値論理が返る。

- **PROVED**: あらゆる単相化・借用経路・将来のコンパイラ改版に対して、必ずコンパイルできる。
- **REFUTED**: 未来の単相化の反例をひとつ、反証トレース付きで差し出してくる。
- **UNKNOWN**: 自らの証明限界を「ファイル・行・該当変数・リスク確率」付きで告白する。

開発者はUNKNOWNの中身を自分のリスク許容度で「入札」し、コミット可否を決める。コミットに `.qed` を添付すると、CIの役割は反転する——CIはビルドの再実行ではなく、**証明書の外部監査**になる。証明書の嘘をスポット検証し、実ビルドは「省略」ではなく「自分の欺瞞を検査する場」としてのみ存在する。

## (4) Rustの4強みが必須の理由
- **性能**: 証明エンジンは「あらゆる未来のコンパイル」を現在の20msでエミュレートする。GCの一時停止が入る言語では、この0.02秒の嘘が証明全体の嘘になる。
- **安全性**: 証明者が自分自身に未定義動作を持つ瞬間、その証明は自己反証となる。「安全なコードからUBが出ない」というRustの構造だけが、自己整合な証明器の土台になれる。
- **依存の少なさ**: 証明とは「根のない信頼」を断ち切る行為。四層の推移的依存がある時点で監査鎖は腐敗する。単一クレートの核心だけが証明の出発点として許される。
- **単一バイナリ配布**: `.qed` が最も活きるのはエアギャップ・法的壁の向こう側。信頼を物理手渡しで伝播できる唯一の形態が単一バイナリである。

## (5) 最も近い既存ツールと決定的な違い
最も近いのは `cargo check`。しかし `cargo check` は現実のソースへ現実の型推論を走らせ、「今この状態では通るか」を毎回すべての状態を再計算して答える実在の計算だ。`Simulacrum` は「このソースがあらゆる正当な将来の単相化・あらゆるコンパイラ改版で通るか」を、現実を一度も作らずに裁定する。そして最も致命的な違いは、`cargo check` が持たない **UNKNOWN が第一級市民**であること。既存ツールは「エラーか成功か」の二値しか知らないが、本ツールは自分が知らない範囲の量を数え、値段を付け、開発者に賭けさせる。開発者の祈り「エラーが出ませんように」は、「自分の無知に値段を付け、そこだけ現実に賭ける」というゲームに置き換わる。

## 具体例
開発者が `fn accept(&self, req: &mut Request) -> bool` を `fn accept(&self, req: impl Into<Request>) -> bool` に書き換えた。旧ワークフローでは `cargo build`（2分）で型エラーと借用エラーを順に潰していた。新ワークフロー: `sim` を叩くと20msで `.qed` が返る——「PROVED: 全単相化で必ずコンパイルできる」「PROVED: 呼び出し側の `req` の借用は、変更後シグネチャの最初の使用点で必ず終了する」「UNKNOWN: `caller.rs:187` に `req` を3回参照渡ししている呼び出し元が存在。リスク0.6%」。開発者の許容度は0.5%なので、その一行だけ実ビルドに賭ける委任トークンを添えてコミットする。CIは `caller.rs:187` の周辺だけを実ビルドし、監査を終える。総所要時間は2分 → 20ms＋スポット監査1件。

## 【持続される矛盾】
本草案は相容れない四つの立場を同時に極限まで押し込み、どれも捨てない。
- 「コンパイラは絶対に実行されない」という否定
- 「実行されたのと同じ意味論を完全に証明する」という全知
- 「証明は意図的に不完全で、その不完全さ（UNKNOWN）こそが商品である」という欠陥の商品化
- 「このツールが完成したとき、開発者にはもはや必要ない——最終版の `sim` は何も出力しない」という自己消滅

それらを全部残したとき、このツールは「成功が消滅と同値なビルドツール」——すなわち、ビルドツールであることを自らやめるためのビルドツール——にしかならない。道具とは行為を省くものだが、`simula` が最終形に達したとき、省かれる行為は「道具を使うこと」だけが残る。
