**【核心的主張】**

アプリケーション開発者の「機能をコードに書きPRで説明する作業」を「実現したい世界の宣言」に置き換える。そして宣言だけが開発行為になった瞬間、その使用者はもはや開発者ではない——PHANTOMは自らのユーザー階級を廃絶することで市場を「開発者3000万人」から「意図を持つ全人類80億人」へ拡張する、カテゴリー自殺型ツールである。

**(1) ツール名（仮称）** — **PHANTOM**。ソースコードを書かせない。OSS宇宙全体（公開リポジトリ・crate・設定パターン）を実装メモリとして、宣言された意図から「最小の検証済み差分」を合成し、実装が不要なら「No」そのものを証明として返す自己終焉型コンパイラ。

**(2) 対象ユーザーと現在のワークフロー** — アプリケーション開発者（Web/モバイル機能実装担当）。現在：要件→手書き実装→PR→レビュー→CI修正→マージ。実装コストの90%は「既に世界のどこかが解いた問題の再実装」に消えている。

**(3) 新しい枠組みで変わる動作の流れ** — `phantom want "WebAuthnにリカバリコードを追加"` と宣言するだけ。(a) 全公開コードを横断検索し、(b) 自社コードベースに適用可能な最小差分を合成、(c) 生成物のメモリ安全性と権限境界を形式検証、(d) 設定変更で達成可能なら「実装不要」と拒否する。成果物は「検証済み差分」か「否定証明」である。

**(4) Rustの4強みが必須の理由**
- **性能**: 検索空間は数億ノードの意味グラフ。キーストローク毎の対話応答はRustの計算量でしか成立しない。
- **安全性**: 第三者のコードを切断・再接合する以上、生成物自体のメモリ安全性を証明系で保証する必要があり、その証明器の健全性はRustの保証に載っていなければ循環する。
- **依存の少なさ**: OSS宇宙の索引は同梱せず、単一二進体が起動時に署名付きで取得する。信頼のルート＝唯一の署名検証に収束する。
- **単一バイナリ配布**: PHANTOM自身が実行基盤（VMなしでコンパイルと検証を内蔵）。「この1ファイルだけを信じる」という堅いtrustモデルが、宇宙を前提とする道具で唯一の安全な配布形態である。

**(5) 最も近い既存ツールと決定的な違い** — GitHub Copilot / Dependabot。Copilotは文脈の「次の行」を予測するテキスト補完。PHANTOMは宇宙全体から最小検証済み差分を合成し、不要なら「No」を返す。否定が成果物になるツールは歴史上初めてであり、「道具は作用を生む」というツールの前提そのものを破棄している。

**具体的利用例** — フィンテック開発者が `phantom want "WebAuthnログインにリカバリコード"` と宣言。10分後、PHANTOMは既存OSS実装を自社コードへ適応させた検証済みPRと、「既存crateの設定2行で充足。実装不要」という否定証明を併せて提示する。3日分の実装が10分と選択肢に変わる。

**メタ・テーゼ（非両立3立場の同時極限化）**: (1) PHANTOMは開発者を救う——実装苦役から解放し判断に集中させる。(2) PHANTOMは開発者階級を廃絶する——最終版 `phantom --zero` は宇宙の意味索引を自バイナリに封入し、「開発者ツール」というカテゴリをOSの一部へ溶解させて消滅する。(3) PHANTOMは成功するほど作用が消える——最も完璧な応答は「何もしなくてよい」の証明であり、究極の成功条件は自らの不要化である。市場価値はこの矛盾の先にしかない。
