# 出力形式（OutputFormat）

- 成果物種別: ツールコンセプト提案書
- 説明: Rustの強みを設計の根幹に組み込み、既存ツールでは実現できない新しい開発ワークフローの枠組みを持つ、具体的で尖ったOSS開発者向けツールのコンセプトを説得力ある形で提示する提案書。
- 出力長の範囲: 3000〜12000 字
- 成果物そのもの: いいえ（成果物についての分析）

## 草案の形式指示（draft_guidance）

各草案は、テーゼ形式で「どの開発者のどの作業を、何に置き換えるのか」を核心的主張として1文で述べよ。続いて、(1)ツール名(仮称可)、(2)対象ユーザーと現在のワークフロー、(3)新しい枠組みで変わる動作の流れ、(4)Rustの4強み(性能・安全性・依存の少なさ・単一バイナリ配布)がこのツールに必須である理由、(5)最も近い既存ツールと決定的な違い、を箇条書きで書け。必ず具体的な利用例を1つ含め。概念の骨子と尖りが分かれば十分。

## 最終化の形式指示（finalize_guidance）

最終成果物は以下の見出しを持つ提案書として整える。「1. タイトル」「2. エグゼクティブサマリー(核心的主張)」「3. 現状の課題」「4. ツールコンセプト」(4.1 対象ユーザー、4.2 新しい枠組み、4.3 具体的な動作例)、「5. Rustの強みの設計的活用」、「6. 既存ツールとの差別化」、「7. ワークフロー変革のストーリー」、「8. 実装・配布・採用の現実性」、「9. リスクと機会」、「10. 結論」。各項目に根拠と具体例を明示し、第6節で提案が「既存ツールの単なる改良」でないことを明確に論じる。1つの尖ったツールに絞るか、複数案の場合は各案に同一構造を与えて比較可能にする。
