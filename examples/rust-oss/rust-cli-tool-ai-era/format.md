# 出力形式（OutputFormat）

- 成果物種別: CLIツール提案書
- 説明: Rustの特性を活かし、AI時代の具体的な痛みを解消する、実装可能なほど具体的でシンプルなCLIツールの提案であること。
- 出力長の範囲: 1000〜3000 字
- 成果物そのもの: いいえ（成果物についての分析）

## 草案の形式指示（draft_guidance）

個々の草案は「1ツール提案」を1本だけ書くこと（列挙は禁止）。以下の要素を必ず含むテーゼ形式で書け：①ツール名と一行キャッチコピー、②解消する課題と対象ユーザー（AI時代のどの痛みか）、③主要機能3〜5個（実際のコマンド使用例を添える）、④Rustを選ぶ理由（性能・安全性・単一バイナリ・エコシステム等のうち明確な根拠）、⑤シンプルさの根拠（実装規模や依存を絞る工夫）。「ChatGPTラッパー」のような安直な案は差別化点がない限り避け、具体性（入力・出力・挙動のイメージ）を重視せよ。

## 最終化の形式指示（finalize_guidance）

複数草案を止揚し、最終成果物を以下の見出し構成の提案書として確定せよ：①タイトル（ツール名＋キャッチコピー）、②概要（3文以内）、③背景・課題（AI時代のどの利用場面で生じる痛みか）、④主要機能（コマンド例を交えて具体的に）、⑤対象ユーザーと利用シーン、⑥Rustを選ぶ理由、⑦シンプルさの根拠（実装規模の概算・非機能要件）、⑧期待される価値と将来性。各草案の最良要素を統合し、1本の具体的なツール提案に絞り込むこと。根拠は材料の範囲内で誠実に述べ、現実の実装可能性を損なう過剰な拡張はしない。
