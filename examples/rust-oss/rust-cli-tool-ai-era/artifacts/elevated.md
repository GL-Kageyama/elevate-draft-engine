## ①タイトル

**`印`（しるし）** ——「AIに何を渡すか、何が渡ったかを、あなたのものとして。」

## ②概要

AI時代に必要な道具は、モデルを改良するものではなく、人間がモデルと共に行為する仕方を保全するものである。`印`は、渡す入力（意図）、渡った記録（記憶）、その主体（署名）の三つを一つの追記型台帳で結ぶ、境界のCLIだ。三つの原器だけで、人間とAIの相互作用を「取引」から「実践」へ高める。

## ③背景・課題

生成の瞬間はブラックボックスであり、「何が渡ったか・それが誰のものか」が不透明になる。入力は無防備（機密の意図せぬ漏洩）、出力は未固定（後日検証不能）、そして気づかぬうちに自分の声が機械の平均へ収斂していく。この三つの痛みは別々の問題ではなく、一つの行為の完全性が崩れた姿である。

## ④主要機能

```
印 seal  文脈.txt -m 'APIキー|社内'   # 計量（tiktoken）・遮蔽（regex/zeroize）・意図の印
印 note  -s <sealのID>                 # blake3ハッシュ連鎖台帳へ行為を追記
印 prove <記録ID>                      # 「意図・真実・主体」の三問に検証で答える
印 voice --since <過去の文書>          # 声の経年変化を汚染でなく成長として映す（任意）
```

`note`をプロンプトの前後に挟むことで、`seal`で定めた意図と生成の要約が一行の改竄不能レコードに閉じ込められる。`prove`はそのレコードを辿り、三つの問いに答える。`voice`は過去の書きぶりとの距離を「侵食」ではなく「変化」として映す。

## ⑤対象ユーザーと利用シーン

AIを日常の業務・制作に使う個人と小組織。契約書・コード・記事など「後で言い分が必要になる」生成、チームでのAI利用の帰属と費用の可視化、そして自分の声を失いたくない書き手——全員に共通するのは、取引の向こうに自分の行為を残したいという欲求である。

## ⑥Rustを選ぶ理由

境界を守る道具自身が信頼できなければならない。メモリ安全、zeroizeによる消去の型強制、ランタイム不要の単一バイナリは、台帳の改竄耐性と機密の確実な消去という約束の素材的保証に一致する。また、人間の連続性を扱う道具は自らも連続的でなければならない——どのAIベンダーが消えても動き続ける。

## ⑦シンプルさの根拠

三つの契機には三つの原器しか要らない。約2千行、依存はclap・blake3・tiktoken-rs・regex・zeroize・serdeのみ。ネットワークなし、AIなし、デーモンなし。シンプルさは引き算の結果ではなく、「行為の完全性がちょうど三つの動きしか要求しない」という構造的な発見である。

## ⑧期待される価値と将来性

この道具は「人間とAIの関係が取引から実践へ移行する」という賭けに立つ。記録は将来の監査・規制・訴訟のインフラになりうるが、それは現在の使用者に価値を与えることで初めて蓄積される。遮断は「防止したことの証明」へ、記録は次の行為の文脈（媒質の記憶）へ高められる。`印`はモデルより長生きし、人間の連続性に仕える。
