# keiro（経路）— エージェントを「実行」ではなく「証明」へ

## 核心的主張

エージェントの信頼性は実行時に観測するものではなく、ビルド時に証明するものである——`keiro`（経路）は、ツール呼び出しを「現在状態から遷移可能な型」として検証し、未定義ツール呼び出し・コンテキスト予算超過・並列分岐のデータ競合を**コンパイルエラー**へ昇格させる、Rust製エージェントループ・コンパイラだ。LangChain型の動的解釈ループは事故を必ず本番まで送り届けるが、keiroの出力は単一バイナリで「ビルドが通った時点で脱線経路が存在しない」エージェントになる。そして本提案が語り継がれる逸話は「**ジュニア開発者に壊れたエージェントを出荷させることが物理的に不可能な現場**」であり、機能差ではなくこの物語こそが模倣を拒む核である。

## 根拠

- LangChain等のPython基盤はツール呼び出しを実行時ディスパッチで解釈するため、スキーマ不一致・レース・無限ループは全て実行時にしか顕在化せず、最初の事故は必ず本番で起きる。
- Rustの所有権は、並列分岐が共有コンテキストを同時書き込みするコードをビルドが拒否できる唯一の機構であり、ロックと非決定的順序に依存するPythonの並列エージェントを構造的に廃絶する。
- コンテキスト枠の上限を型として強制すれば、文脈予算の破綻は実行時打ち切りではなくビルド失敗となり、反復回数・停止条件も型レベルで検証対象になる。

## 前提

対象はPythonエージェント基盤のスケール限界と非決定性に達した中〜上級開発者（数十人規模のチーム）で、Rust習熟コストを投資とみなす層に絞る——これにより本ツールは「誰でも使える移植」ではなく「Rustでしか成立しない唯一の主張」として競合の安全圏の外に立つ。
