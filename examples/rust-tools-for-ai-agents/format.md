# 出力形式（OutputFormat）

- 成果物種別: ツールコンセプト設計書
- 説明: エージェント開発者の特定の課題（コンテキスト管理・ツール呼び出し・エージェントループ・並列性・信頼性のいずれか）に対して、Rustの強みを核にした具体的で差別化された1つのツールを、競合との違いと実装可能性まで含めて設計する成果物。
- 出力長の範囲: 1200〜5000 字
- 成果物そのもの: いいえ（成果物についての分析）

## 草案の形式指示（draft_guidance）

分析系のテーゼ形式（核心的主張／根拠／前提）で各草案を書け。核心的主張=「どの課題にどのツールを」を1文で明示（ツール名・対象課題・Rust採用の核となる理由）。根拠=既存ツール（LangChain等の汎用フレームワークやPythonエージェント基盤）の不足点と、Rustのどの強み（性能・安全性・軽量バイナリ・単一バイナリ配布）がその不足をどう解決するかを対応付けて具体的に示す。前提=想定ユーザー（エージェント開発者の規模・技術層）、利用シーン、競合状況を明記。既存ツールのRust移植ではなく、Rustならではの独自機能・差別化要素を必ず1つ以上含めること。

## 最終化の形式指示（finalize_guidance）

汎用のTarget/Value/Risk/Opportunityを以下に置き換え、この順序で最終成果物を構成せよ。(1)ツール名と一言キャッチコピー、(2)対象ユーザーと解決する課題（タスクの5課題カテゴリのどれに対応するか明示）、(3)中核機能（3〜5個、各機能にRustの強みとの対応を明記）、(4)差別化（既存ツールとの比較表または対比記述と独自機能の説明）、(5)想定アーキテクチャ（主要クレート・単一バイナリ配布の形態）、(6)MVPスコープと実装ステップ、(7)リスクと制約（市場・技術的限界）。具体名（クレート名・機能名・数値目標）を伴わせ、汎用フレームワークとの差別化が明瞭な形で記述せよ。
