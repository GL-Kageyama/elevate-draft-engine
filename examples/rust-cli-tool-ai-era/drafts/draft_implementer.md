## ① ツール名と一行キャッチコピー

**`cork`** ——「LLMに流れ込む一滴の秘密を、物理的に止める。」

## ② 解消する課題と対象ユーザー

AI時代の事故は必ず**「漏れた後に気づく」**。既存の秘密検知ツール（gitleaks系）はリポジトリを事後スキャンする敗北主義で、データが一度モデルのパイプラインに入った時点で手遅れだ。本当に必要なのは「外へ出る直前」＝`|`（パイプ）のその瞬間に秘密を掬い取る防波堤。対象は、差分や設定ファイルを無造作にプロンプトへ流す全開発者と、機密を扱う金融・医療・SIerのチーム。**スキャンではなく遮断**を約束する。

## ③ 主要機能とコマンド例

- **ストリーミングredaction**（標準入力→標準出力、状態を持たない通過フィルタ）
```
$ git diff | cork | claude -p "この差分をレビューして"
# APIキー・JWT・秘密鍵は <redacted:aws_access_key> に置換されて通過
```
- **フォーマット認識**。JSON/TOML/YAMLの構造を壊さず値だけを隠す
```
$ cat prod_creds.json | cork --format json > safe.json
```
- **チーム共有ポリシー** `.cork.toml`（許可パターン／禁止パターン／隠し形式）
- **CIゲート**
```
$ cork check --strict .   # 1つでも秘密を含めば exit 1。デプロイを物理的に止める
```
- **注入検知**（保守的・高精度で、通常は標準入力を阻害しない）
```
$ cork injection agent.md # プロンプトインジェクション様断片を警告
```

## ④ Rustを選ぶ理由

本ツールの唯一の約束は**「秘密はメモリからも確実に消える」**こと。Rustの`zeroize`はdrop時のゼロ埋めを型で強制するが、GC言語ではイミュータブル文字列がコピーされ回収タイミングを制御できず、この約束が構造的に不可能。加えて、巨大ペイロードを丸ごとバッファしないストリーム処理、`cargo.lock`で依存を固定した静的単一バイナリ（監査可能・CIにpin可能）は、**「供給網攻撃から守る道具自身が供給網であってはならない」**という要件に直結する。asyncもtokioもdaemonも不要。

## ⑤ シンプルさの根拠

約2.5k行、依存は`clap`/`regex`/`zeroize`/`memchr`/`serde`+`toml`の5つのみ。ネットワークなし・状態なし・ログなしのステートレス通過フィルタで、実体は「(パターン, マスク)の規則リストを流し込む1本のホットループ」に尽きる。検知はモデルでなく、**誤検知ゼロに倒した高精度・低再現のヒューリスティック**——誤検知するデータはそもそも通過させるべきではない。通過速度より「絶対に漏らさない」ことを選ぶ。この引き算こそが、監査される側に立つ道具の誠実さだ。
