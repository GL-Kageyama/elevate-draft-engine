## kagami（鏡）——「AIが全員を平均にする。鏡だけが、君を君に戻す。」

### ② 解消する課題と対象ユーザー
AI時代の最深の痛みは非効率ではない。**自分の声が、本人すら気づかないうちにAIの平均とすり替わっていること**だ。下書きを任せ、メールを整え、日記を書いてもらい……一年後、自分がかつてどう書いていたか思い出せない。対象は、AIに文章を書かせて「なんだか自分じゃない」という違和感を抱えたすべての人——作家、研究者、学生、そして日記を預けてしまった人。kagamiは禁止も採点もしない。ただ映す。**名前のつけられなかった違和感に、ようやく形を与える。**

### ③ 主要機能
```
kagami init ~/writings/*.md           # 過去の文章から「あなたの声」の基準を作る
kagami check draft.md                 # 段落ごとに「あなた度」と、理由になる一文
kagami borrow draft.md                # あなたらしくない文だけを抜き出して晒す
kagami drift --since 2025-01          # 声の経年変化。AIに侵食された月が特定できる
kagami reclaim draft.md > mine.md     # 借りた文を除き、あなたの文だけを取り戻す
```
checkの出力はスコア表ではなく、鏡の言葉だ。**「この2文、君らしくないね。君なら『〜だけど』で繋ぐのに。」** 入力はMarkdown/テキストのみ。ネットワークなし。この道具には、収益も効率も、あえて一切ない——**効率の時代に、速度を捨てて自分と向き合うための道具である。**

### ④ Rustを選ぶ理由
kagamiが扱うのは「その人の最も私的なデータ＝言葉」だ。メモリ安全は流行りではなく責務である。そして**単一バイナリは永遠性の比喩**だ——Python環境もモデルのダウンロードも不要で、AIサービスが終焉してもこの鏡だけは動き続ける。声の永続を扱う道具は、自らも永続的であるべきだ。加えて、数千文書の文体分析を数ミリ秒で返す速さは、振り返りを億劫にさせない。鏡を覗くのは、待たされてよい行為ではない。

### ⑤ シンプルさの根拠
文体分析は誰もが思うより単純である。**文字n-gram（n=3〜5）と機能語頻度と文長分布**——たったこれだけで、文体は驚くほど特徴づけられる。依存は `clap` と `serde_json` のみ、実装約1,800行。声のプロファイルはgitで差分管理できる50KBのJSON——**あなたの声が、バージョン管理される。** 機械学習もAPIも要らない。鏡は、ただの鏡であれ。

---

*この提案は「収益」とも「効率」とも正面から衝突する——それが発散の意図である。kagamiは利益を生まず、作業を遅くし、ただ一人の人間を自分の言葉に返す。それこそが、この時代に最も必要なものだと私は主張する。*
