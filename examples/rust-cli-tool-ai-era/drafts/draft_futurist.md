# Futurist 草案: `alibi`

**核心的主張（3文）**
生成AIの経済的価値は、未来で「生成の速さ」から「生成物の過去の証明」へと反転する。今は誰も記録していない「どのモデルが、どのプロンプトで、何を・いつ作ったか」の改竄不能な累積記録こそ、5年後に最も高い複利を生む唯一の資産になる。だから私は、AIを一切呼ばない「記録と検証だけ」のRust製CLIを提出する——現在の市場でこれを買う者はいないが、5年後に買えない者はいなくなる。

---

**①ツール名と一行キャッチコピー**
**`alibi`** — 「機械が言ったことを、後から証明できるようにせよ。」

**②解消する課題と対象ユーザー（AI時代のどの痛みか）**
AI時代の痛みは「生成が足りない」ことではなく「生成したことが蒸発する」ことだ。同じプロンプトは明日には別の出力になり、モデル更新で挙動が静かに変わり、1年後には「このコード誰が・何で作った?」に誰も答えられない。この記憶喪失は規制監査（金融・医療）、研究の再現性、AI生成コードを本番に載せる開発者を確実に蝕む。対象は今の市場ではなく、5年後に説明責任を問われる全員である。

**③主要機能（コマンド例）**
- `alibi record -m gpt-4o --prompt 'リファクタ案' -i src/ -o out.diff` — モデル・プロンプト・入力ハッシュ・出力ハッシュを連結して台帳に追記。
- `alibi verify out.diff` — ハッシュを再計算し台帳と照合。改竄・素性不明を検出し「記録なし」で拒否する。
- `alibi log --since 30d` — いつ・どのモデルで・何トークン使って・何を作ったかを照会。人間の承認/却下判定も記録。
- `alibi diff out.diff` — 同一プロンプトを今日のモデルで再実行し、昨日の出力とのドリフトを可視化。非再現性を曝露する。
- `alibi pin` — 再生成環境（モデル・温度・シード・コンテキストハッシュ）を `alibi.lock` に固定。**`Cargo.lock`のAI版**。

**④Rustを選ぶ理由**
監査・証拠保全は本番・法廷・規制現場で動く。ランタイムなしの単一バイナリで、ビルド不要のまま5年後も動き続ける。改竄防止を売りにするツール自身がメモリ安全でなければならない——脆弱性ゼロは絶対要件。blake3のハッシュ計算と台帳スキャンはRustの性能が活き、100万レコードでもミリ秒応答を維持する。

**⑤シンプルさの根拠**
依存は `clap`・`blake3`・`serde_json` の3つだけ。AI APIを呼ばないためネットワーク不要・モデル非依存・ベンダーニュートラル——これ自体が「ChatGPTラッパー」との決定的差別化点である。台帳は「前レコードのハッシュを次に含める」チェーン構造の追記専用JSONLで、原理はgitと同一。実装は約2,000行、データはユーザー手元にだけ残り、いかなるサービスにも依存しない。

**前提**: 生成AIへの記録要求が法制・規格として標準化される（欧州AI法以降の必然の流れ）。
