## 草案：`dashi`（出汁）——AIを内蔵しない、AI時代の唯一の高レバレッジ・ツール

### ① ツール名と一行キャッチコピー
**`dashi`** ——「出汁は料理に見えない。だが味の八割を決める。AIに渡す文脈を、計り、濾し、整えよ。」

### 核心的主張（デザイナーの眼）
AIの出力の上限を決めるのはモデルではない。モデルに渡る**文脈**である。にもかかわらず、この時代で最も品質を左右する一瞬——プロンプトの組み立て——は、今も素手の `cat` と手動コピペで行われている。あらゆる工程にAIが接続されていく今、最も過激な差別化は**AIを一切呼ばないこと**だ。`dashi` はLLMに触れず、決定論的で、オフラインで、無料で、それでいてあらゆるLLMの出力を底上げする。「AIツール」でありながらAIが無い。これが反転だ。

### ② 解消する課題と対象ユーザー
「入力の質こそ、出力の上限である」。過剰で、重複し、機密を含んだ文脈を渡せば、どんな高級モデルも平凡な答えしか返さない。その瞬間の注意力——トークン数・秘匿・関連度・差分——を、今は全部人間の目と手に頼っている。対象は、コードを毎日チャットAIに貼る開発者、エージェントループやevalを回すチーム、秘密情報を抱えたリポジトリを持つ全員。この道具の美は「何もしすぎないこと」にあり、その作法が守るのは、他でもない使用者の金と時間と信用である。

### ③ 主要機能（コマンド例）

```console
$ dashi scan .                 # トークン版 du
 総計 312k tokens / 1,204 files
 src/lib.rs    41,200  ████████████ 13.2%   secret: 1
 vendor/       88,900  █████████████████████ 28.5%  ← 除外候補
```

```console
$ dashi prep src/ --focus "token auth" --budget 16k
 ✓ 47 files → 23.1k tokens（予算超過）
 ✓ 順位付け: 11 files 保持 15.9k / 9 files 要約
 ✓ 秘匿: 3件をマスク   [GH_TOKEN=…, sk-…, 社内path]
 完成 15.9k tokens / 1.8s — クリップボード済み（⌘V）
```

```console
$ dashi redact config.rs       # 機密マスクを単体で（CIで -c 検証）
$ dashi diff .                 # 前回 manifest との差分だけ抽出
 +src/auth.rs (+1.2k)  -tests/old.rs (−0.9k)  Δ350 tokens を渡せば続きが紡げる
```

### ④ Rustを選ぶ理由
オフラインでモデルと**同一の**BPEトークン数を出すには `tiktoken-rs` が要る——Rust製参照実装との親和性は他に並ばない。そしてこの道具の美は「速さ」にある。`regex` + `ignore`（ripgrep級）で数万ファイルをミリ秒で走査する手触りこそが作法を支え、単一バイナリの `cargo install dashi` は置き物にならない。さらに、誰のマクロが来るか分からない任意コードベースを喰う以上、メモリ安全は倫理である。

### ⑤ シンプルさの根拠
非同期もHTTPもサーバもプラグインも無い。「経路→濾過済みバイト列」の一方向バッチで、起動して報告して終わる——`ripgrep` と同じ哲学。依存は `clap` `ignore` `regex` `tiktoken-rs` `serde` のみ、本体は約1,500行、設定ファイルゼロ。AI時代に「何も足さない」ことを選ぶのは、機能の欠如ではなく、最高の設計判断である。

**前提**: 文脈の質はモデルの質に先立つ——この信念が揺らぐ日まで。
