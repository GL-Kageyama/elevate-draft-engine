# 前提知识的注入（--knowledge）

把任务附带的素材・约束・背景信息（材料、目标人群、价格带、资料等）作为生成的根基
注入所有阶段。与 fmt（形式的约束）相对的**内容的约束**，二者正交:

```
Task → 【前提知识】 → 【本任务的草案形式 / 最终成果物形式】（fmt）
```

| CLI | 行为 |
|---|---|
| `--knowledge "材料: 再生PET。目标: 20〜30代。"` | 直接指定知识 |
| `--knowledge-file PATH` | 从文件读取长篇资料・设计信息 |
| `--ask-knowledge` | 启动时交互式输入（Ctrl+D 结束） |

## 注入范围

- 指定的知识作为任务紧随其后，注入 **diverge（草案）/ aufheben（扬弃）/ finalize（最终化）/ generate（单次）** 的
  全部生成阶段。防止超出素材的捏造，使成果物不与知识矛盾。
- **不注入 extract_format**——形式提取（形）只从任务进行，不混入知识（内容）。
- **不注入五维评估**——政策固定。在生成根基的范围之外。
- **在 improve 的修改轮次中持续存在**——因为 diverge 在内部附加知识，所以不会跨轮次丢失。
- **compare 是公平的**——也给单次生成基线注入同样的知识后比较。
- 指定的知识保存到 `--out/knowledge.md`（与 input.md / format.md 并列・透明性）。
- 无知识（传统行为）则完全不注入。三种指定方法相互排斥。
