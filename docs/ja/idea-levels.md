# 発想レベル（--idea-level）

発想レベルは、発散（diverge）と昇華推理（Aufheben）がどこまで極端に踏み込むかを選ぶ。**2つのレバー**で適用する: 段階的な**発散ヒント**（主レバー）＋**温度**（補助レバー）。2レバー設計の理由は、reasoning モデル（ゲートウェイ経由の deepseek-v4-pro）が温度 1 越えを確実に反映するとは限らないため。ヒントがプロンプトで「より極端」の意味論を担い、温度がサンプリングでそれを補強する。

| レベル | 温度 | 意味 | 発散/昇華ヒント |
|---|---|---|---|
| `standard`（既定） | 0.9 | 一般的に極端 — 従来の挙動（後方互換） | `[発散を重視]` |
| `very` | 1.2 | 非常に極端 | `[非常に極端な発散を重視]` |
| `extreme` | 1.5 | 極度に極端 | `[極度に極端な発散を重視]` |

最終化はレベルに関わらず常に温度 **0.0**。

## 2レバー設計の根拠（調査所見）

- **温度 1 越えはゲートウェイが受理する。** 実API呼び出しで DeepSeek の Anthropic 互換エンドポイントが温度 1.2・1.5 をエラーなく受理することを確認した。調査当初の問い「温度の1越え設定の可否」への答えは——はい、1 越えは設定可能。
- **reasoning モデルでは温度単独は確実なレバーにならない。** ゲートウェイの reasoning モデルは拡張思考ブロックを経由して回答するため、単一サンプルの調査では温度単独で「より極端」な出力が実測できることを証明できなかった。そこで意味論は主にヒントが担い、温度は補強に使う。
- **適切なパラメータ値**（「どの程度のパラメータが適切なのか」への答え）: レベルは 0.9 / 1.2 / 1.5 の単調な梯子にした。1.5 を超える値は支離滅裂のリスクが高く、0.9 は既定挙動を従来リリースと完全に同一に保つ。

## エンジンごとの動作

| エンジン | レベルの適用方法 |
|---|---|
| `sdk`（既定） | 温度とヒントの両方を API に渡す |
| `claude-code` | 温度つまみなし（`claude -p`）。ヒントのみでレベルを近似 |

`sdk` エンジンは **`idea_level` が明示指定されたときだけ**ヒントを注入するため、既存の温度のみの呼び出しは従来どおりの挙動を保つ。`claude-code` エンジンは発想レベルを優先（3段）、未指定時は従来の温度ベース2段ヒントへフォールバックする。
